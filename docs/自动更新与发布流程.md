# 自动更新与发布流程

本文档说明 cute pet（桌面小猫）的版本发布与客户端自动更新机制。

## 一、整体链路

```
发布者本机（macOS）
  ① ./release.sh v1.0.004 "更新说明"
     ├─ 写入版本号（AppVersion.swift + Info.plist 自动同步）
     ├─ Swift 编译 → 打包 cute pet.app → 签名（ad-hoc）
     ├─ 压缩 zip → 计算 sha256
     ├─ Ed25519 签名（私钥仅存本机）
     └─ 生成 latest.json
  ② 上传到公网服务器 /opt/petserver/dist/
                    │
                    ▼
客户端（任意已安装 cute pet 的 Mac）
  ③ 检查更新：启动 30 秒后 / 每 6 小时 / 右键菜单手动触发
     GET /api/app/latest → 比较版本号
  ④ 有新版本 → 弹窗确认「立即更新」→ 下载 zip
  ⑤ 校验 sha256 → 用内置公钥验 Ed25519 签名
  ⑥ 弹窗确认「重启并更新」→ App 退出 → 脚本替换 .app → 自动重新打开
```

## 二、组成部件

| 部件 | 位置 | 作用 |
| --- | --- | --- |
| 发布脚本 | `DesktopPetForMacApp/release.sh` | 编译、打包、签名、上传（一条命令完成） |
| 打包脚本 | `DesktopPetForMacApp/package.sh` | 组装 .app、签名；`SKIP_DESKTOP_COPY=1` 用于发布（不动桌面版本） |
| 版本号 | `DesktopPetForMacApp/DesktopPetForMacApp/App/AppVersion.swift` | 唯一版本源，打包时自动同步到 Info.plist |
| 客户端更新器 | `.../DesktopPetForMacApp/Services/UpdateService.swift` | 检查/下载/验签/换包，内置发布公钥 |
| 服务端接口 | `PetServer/internal/controller/release_controller.go` | 下发版本信息、提供安装包下载 |
| 发布目录 | 服务器 `/opt/petserver/dist/` | 存放 `latest.json` 与各版本 zip |
| 签名私钥 | 发布者本机 `~/.cute-pet-release/ed25519_private.pem` | 离线保管，**不入库** |
| 上传助手 | `~/.cute-pet-release/scp_put.exp`、`ssh_run.exp` | 免交互上传/执行（expect 脚本） |

## 三、服务端接口

### GET /api/app/latest

返回最新版本元信息；未发布任何版本时返回 404 `no release published`。

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "version": "v1.0.003",
    "file": "cute-pet-v1.0.003.zip",
    "sha256": "fd45c38d9e71...",
    "signature": "base64(Ed25519 签名)",
    "notes": "更新说明",
    "publishedAt": "2026-10-15T16:34:00+08:00",
    "size": 3636796,
    "minOS": "13.0"
  }
}
```

- `signature` 的签名对象是 **`sha256` 的十六进制字符串**
- 客户端必须同时通过「摘要比对」与「签名验证」，任一不过直接拒绝安装

### GET /download/<file>

下载安装包（zip）。仅允许访问 dist 目录内文件，防目录穿越。

## 四、发布步骤

### 前置条件

- macOS + Swift 工具链（`swift build` 可用）
- 签名私钥 `~/.cute-pet-release/ed25519_private.pem`（首次需生成，见附录）
- 上传助手脚本存在，且服务器 root 密码确认无误

### 发布

```bash
cd DesktopPetForMacApp
./release.sh v1.0.004 "本次更新说明（会展示给用户）"
```

脚本执行 6 步：写入版本号 → 编译打包 → 生成 zip → sha256 + 签名 → 生成 latest.json → 上传服务器。

### 验证

```bash
# 服务端版本信息
curl -s http://101.96.248.75/api/app/latest | python3 -m json.tool

# 下载并比对摘要
curl -s -o /tmp/dl.zip http://101.96.248.75/download/cute-pet-v1.0.004.zip
shasum -a 256 /tmp/dl.zip   # 应与 latest.json 的 sha256 一致
```

### 版本号规则

- 形如 `v主.次.修订`（如 `v1.0.004`），比较时按数值逐段对比（`v1.0.010 > v1.0.009`）
- 支持 `v1.0.001.test` 这类后缀，用于本地开发版
- 版本号变化会触发客户端「清除旧版本校验权限」（需重新输入激活码），这是刻意设计

## 五、客户端行为

| 时机 | 行为 |
| --- | --- |
| 启动 30 秒后 | 首次自动检查（避免影响启动性能） |
| 每 6 小时 | 定时检查 |
| 右键小猫 →「检查更新 🔄」 | 手动立即检查（无更新也会提示「已是最新版本」） |

升级交互（**非强制**）：

1. 「发现新版本 vX」→「立即更新」/「稍后」
2. 下载 + 校验通过 →「更新已下载完成」→「重启并更新」/「稍后」
3. 选择更新：App 退出 → 分离脚本替换 .app 目录 → 自动重新打开

替换失败会回滚（保留 `*.old` 目录并还原）。

## 六、安全模型与边界

**防护能力**

- 安装包完整性：sha256 比对
- 安装包来源真实性：Ed25519 验签，公钥内嵌在 App 里，攻击者无法伪造（除非改 App）
- 升级失败可回滚

**局限**

- 公网链路目前是 **明文 HTTP**：安装包内容可能被抓包者看到（可配合应用层加密缓解敏感数据），但**无法被伪造**
- 未做「防降级」：理论上可诱导客户端安装旧版本（签名有效）
- 签名私钥泄露 = 可发布恶意更新；私钥丢失 = 无法再发布能被老客户端接受的更新（公钥不可更换）

**密钥保管建议**：私钥备份到密码管理器/U 盘；不要提交到 Git（`.gitignore` 已忽略发布产物，私钥本身在用户目录外）。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 检查更新报「无法连接更新服务」 | 服务器不可达/端口未放行 | `curl http://101.96.248.75/api/ping` 验证 |
| 「更新包验签失败」 | 私钥与 App 内置公钥不匹配（换了机器或换了密钥） | 用同一私钥重新发布；必要时重新打包 App 换公钥 |
| 「更新包校验失败」 | 上传中断导致 zip 不完整 | 重新执行 release.sh |
| 发布脚本上传卡住 | 服务器 dist 目录不存在 / 交互密码问题 | 脚本会先 `mkdir -p`；确认助手脚本可用 |
| 升级后需要重新输激活码 | 版本变化清除旧权限（设计如此） | 重新输入激活码即可 |
| 客户端一直是最新版本但功能不对 | 客户端版本号与发布版本相同但内容不同 | **同一版本号不要重复发布不同内容**，必须递增版本号 |

## 八、后续可选项

- **云端编译**：接 GitHub Actions（macOS runner），打 tag 自动编译+签名+上传，彻底免本地编译；私钥存为 CI Secret
- **HTTPS**：加域名 + Caddy 自动证书，更新链路与后台登录一并加密
- **防降级**：客户端记录已安装版本，拒绝低于当前版本的包
- **灰度发布**：按设备 ID 分批下发不同版本

## 附录：首次生成签名密钥

```bash
mkdir -p ~/.cute-pet-release && cd ~/.cute-pet-release
openssl genpkey -algorithm ed25519 -out ed25519_private.pem
chmod 600 ed25519_private.pem
# 公钥（内嵌到 UpdateService.swift 的 releasePublicKeyBase64）
openssl pkey -in ed25519_private.pem -pubout -outform DER | tail -c 32 | base64
```

生成后需将公钥写入
`DesktopPetForMacApp/DesktopPetForMacApp/Services/UpdateService.swift` 的
`releasePublicKeyBase64`，并重新打包发布一次，客户端才会认可后续更新。
